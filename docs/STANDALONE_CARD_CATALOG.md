# Standalone Card Catalog

## Goal

Allow SiteRuneForged to be deployed before the RuneForgedTCG public backend exists.

The portal ships a certified static snapshot of the public Vanilla card catalog and the card art assets required by that snapshot.

## Current snapshot

- RuneForgedTCG source SHA: `4028da3999c168fa43e55c967d2d9cf90d30ebb1`
- release: `2.97.0`
- public cards: **446**
- collection: Vanilla
- source catalog revision: `457:empty`

The snapshot was generated by booting that exact game commit with PostgreSQL and reading the same public card API used by the live portal.

## Runtime behavior

The portal is **API-first**:

1. try `GET /api/public/game/cards` from `RUNEFORGE_API_URL`;
2. if the API responds, render live game data;
3. if the API is absent/unreachable, query the bundled snapshot locally.

Card detail uses the same rule. A real API 404 remains authoritative and does not resurrect a stale snapshot card.

## Art assets

Relative game art referenced by the public DTO is copied into:

`public/standalone-game/`

Snapshot URLs are rewritten to those local portal assets. Therefore the Vercel deployment does not require the game origin to serve card images.

## Switching to the live backend

No code change is required.

When the game is public, configure:

```env
RUNEFORGE_API_URL=https://<public-game-origin>
RUNEFORGE_GAME_URL=https://<playable-game-origin>
RUNEFORGE_EXPECTED_DEPLOY_SHA=<certified-game-sha>
```

Redeploy SiteRuneForged. The card catalog will use the live API automatically.

## Refreshing the snapshot later

Use `scripts/export-standalone-card-snapshot.mjs` against a locally running certified RuneForgedTCG checkout. The exporter validates game deployment provenance, paginates the complete public catalog, rejects duplicate IDs, and copies referenced local art.

The one-time bootstrap workflow used to create the first snapshot is intentionally removed before merge; snapshot refreshes should be explicit release work.
